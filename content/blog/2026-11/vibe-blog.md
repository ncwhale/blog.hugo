# 给博客 vibe coding 了一下！

[2024年的时候](/blog/2024-02/append-htmx-with-hugo/) 就想过要把博客的评论系统用 HTMX 重新实现一遍了，但是一直没有时间去做，直到最近发现 AI 越来越强了，于是就让哈基米帮我把博客的评论系统用 Rust + HTMX 重写了一遍，顺便还帮我把博客的主题也重构了。

## 评论系统 hx-echo

这是我提出方案然后和 AI 讨论最后完全让 AI 实现的评论系统，部是我的个人工程喜好带来的如下特性：

1. 零成本托管！ 你只要使用免费的 Cloudflare worker&D1 即可运行！
2. Hugo 静态化支援！你的全静态化博客在使用合适的 template 之后，评论区也会一并静态化！
3. HTMX 支援的动态增量！即使你的博客没有重新编译，HTMX 驱动的 DOM 事件也会自动将新的评论注入到页面中！
4. 基于 Rust 构建！ I mean, why not? 运行成本远比 V8 低，而且静态类型检查使得编译结果更加可靠。
5. 完美融入整站 hx-boost，解决了当年 Disqus 会导致全页强制刷新的痛点，现在留言也和SPA一样不会刷新了喵！

项目地址：  [Github](https://github.com/ncwhale/hx-echo)

## 给新朋友的极简原理导览

如果你刚点进这个博客，或者也想给自己的静态网站折腾一套轻量化评论系统，可以这样理解这套组合是怎么协同工作的：

### 1. 为什么叫「静态基线 + 动态增量」？

传统的静态博客评论插件（比如早期的 Disqus 或基于 iframe/JS 的方案）往往得等页面全部加载完，再由浏览器从零拉取所有评论，既慢又不利于搜索引擎收录。

`hx-echo` 把这件事拆成了两步：

1. **构建期静态直出（Base）**：每次 Hugo 生成页面时，顺手把当时的历史评论直接打包进 HTML。所以你点开文章的第一瞬间就能看到已有评论，**0ms 额外等待**。
2. **滑到再加载增量（Delta）**：页面打开时并不会急着发请求，只有当你把页面**滑动到评论区进入视线**时，HTMX 才会悄悄问一句后端：“从上次构建到现在有没有新留言？”
   - 如果没有新评论，后端直接回一个空的 `204 No Content`，页面零抖动；
   - 如果有新评论，只把新增的那几条局部插进列表里，连页面都不会闪一下。

### 2. 这套「KuroAka + hx-echo」还藏了哪些小细节？

- **手机与桌面都更顺手**：文章列表现在**点击卡片里的任意位置**（缩略图、摘要、空白处）都能直接打开文章；手机端导航栏改成了**零 JavaScript 的纯 CSS 折叠菜单**，配合 HTMX 切换页面自动收起，不再出现“点菜单没反应”的问题。
- **站内跳转不重载头图**：在站内点击文章、标签、分类或按浏览器前进/后退时，HTMX 只替换中间的内容区域，顶部的看板图和页脚保持常驻，体验像单页应用一样顺滑。
- **支持 Markdown 与跨语言**：评论内容在 Cloudflare 边缘节点完成 Markdown 渲染与 XSS 安全过滤，支持多域名同源挂载，也自带 `en` / `zh-cn` / `zh-tw` / `ja` 及前端 `data-i18n` 扩展能力。

## 亲自试试看新的评论区！

说了这么多，不如直接往下滑一点亲自体验一下喵：

1. **发一条测试留言**：在下方评论区填上昵称，正文支持 **Markdown 语法**（比如 `**加粗**`、`` `行内代码` ``、代码块或列表），点击「发表评论」后**页面不会刷新**，新评论会直接局部插进列表里。
2. **试试楼中楼回复**：随便找一条已有评论，点它右上角的 **回复** 按钮，输入框上方会出现当前回复对象提示，提交后会通过 HTMX 的 OOB（Out-of-Band）机制直接落进对应的回复串里。
